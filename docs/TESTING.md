# 検証記録

v0.1.0の検証内容。2026-10-26更新。

## 自動テスト

`npm test`：15件（本体・状態同期12件、公開前チェック3件）。

- 5分・3回の初期設定、終了時刻ちょうどの遮断、上限到達
- 解放中の再クリックで回数・終了時刻が変わらない
- 保存した状態の再読み込みと、早期終了で回数を返さない
- 設定変更で使用済み回数を保持し、現在の終了時刻を変更しない
- 0時に枠を更新し、前日の解放を継続しない
- 記録済みの時刻を巻き戻した際に、消費済み回数や終了済みの解放が復活しない
- 設定値の範囲検証、使用済み回数より低い上限への変更
- X・InstagramのURLとXの「フォロー中」判定
- 20件の同時解放要求を直列化し、1回として保存
- バックグラウンドを再起動しても状態を復元
- エラーの後も次の操作を処理
- X・Instagramの解放・消費・終了の独立性
- 通信中に届いた状態変更通知を取りこぼさず、完了後に再取得する
- ブラウザのストレージがオブジェクトのキー順を変えても、GETで不要な書き込み・通知を発生させない
- 公開前チェックが作業ツリーではなくGit indexの内容を検査し、強制追加された署名設定を拒否する
- キー形式・トークンを検出した際に値をログへ出さない。バイナリ内の文字列も検査する
- ローカルのTeam IDの混入と、シンボリックリンクを拒否する

`npm run test:browser`：5シナリオ。

Playwright付属のChromiumに `dist/chrome` を実際に読み込んで実行します。`x.com` と `www.instagram.com` への通信はテスト用HTMLに差し替え、サイトの代表的な構造を再現しています。ストレージ、サービスワーカー、メッセージ通信、コンテンツスクリプト、ポップアップは実装本体を使います。

- Xのおすすめを隠し、「フォロー中」に切り替えられる。解放は別タブにも反映される。Instagramは解放されない。リロードでも継続し、早期終了も別タブに反映される。
- Instagramの通常投稿・DMは使え、リールの直接URL、プロフィールのリール、インライン表示を隠す。SPAのURL変更にも追随し、ボタンから解放できる。
- ポップアップで設定を保存し、上限到達後のボタンを無効化。サービスを切り替えると別の残り回数を表示し、リロードでも設定が残る。
- 実際に再生したcanvas由来の動画を、終了時刻に再遮断・一時停止する。テストでは待ち時間を短縮するため、保存した終了時刻だけを約1.5秒後に設定する。
- 前日の枠を更新し、ポップアップと遮断画面をキャプチャ。ページ内のJavaScript例外がない。

画面キャプチャ：`docs/screenshots/popup.png`、`docs/screenshots/x-blocked.png`。Xの画面はテスト用フィクスチャです。

## macOS / Safariアプリ

- XcodeのxcodebuildでmacOSアプリとSafari Web Extensionをビルド。
- 開発者のローカルApple Development証明書を使った署名を確認。証明書・秘密鍵・個人の署名設定・署名済みアプリは公開対象に含めない。
- codesign --verify --deep --strictで、アプリ本体と埋め込み拡張の整合性を確認。両方のTeamIdentifierが一致することも確認。
- アプリの日本語の導入画面と、Safariの拡張機能設定を開くボタンを確認。

**Safari拡張の有効化、Safari内での実行、ログイン済みの実サイトでの最終確認は未実施**。

初回有効化後の確認項目は次のとおりです。

1. Xのホームでおすすめが隠れ、フォロー中だけ閲覧できる。
2. 「5分だけ見る」でXのおすすめだけ解放され、残り回数が2になる。
3. Instagramのリールはまだ遮断されていて、別に解放できる。
4. 期限または「今すぐ閉じる」で再遮断される。
5. 設定変更、リロード、Safari再起動でも設定・当日の消費回数が残る。

DOMフィクスチャでの確認は、実サイトのすべてのA/Bテスト、表示言語、ログイン状態、画面幅、動画表示形式を保証するものではありません。
